Пипка·игры

Игры для TrackPoint · ThinkPad T480 и всё, что старше

«Играл с пипкой — проиграл»

Красная пипка между клавишами G, H и B называется TrackPoint. Она отдаёт не координату, а нажим: внутри тензодатчик, и курсор едет тем быстрее, чем сильнее давит палец. Это не мышь — это миниатюрная ручка управления, которая сама возвращается в ноль, когда её отпускаешь. Эти игры сделаны не «под мышь, которая бывает пипкой», а именно под нажим: там, где обычная игра читает позицию курсора, они читают силу.

Игры

Чему это научило

Обе игры про одно: у органа управления есть собственный характер, и игра получается тогда, когда она сделана про этот характер, а не вопреки ему. Пипка умеет держать усилие и не умеет точно указывать — поэтому здесь нет ни одной задачи на попадание курсором, зато обе игры про удержание дуги. Пипка сама возвращается в ноль — поэтому отпущенный палец означает «прямо», и ни одной игре не понадобилась мёртвая зона в интерфейсе. Пипка ничего не сообщает пальцу в ответ — поэтому и визг покрышек, и индикатор нажима, и телеметрия существуют не для красоты.

И отдельно, уже не про геймдизайн: первые два раза в продакшен уехало ровно то, что я не измерил. Самолёт — потому что я проверил синтаксис, а не ту сборку, которую открывает человек. Машина — потому что я проверил геометрию трассы численно, а динамику оставил «на посмотреть глазами». Проверка физики, которую стоило написать сразу, нашла пять багов за один прогон, включая три, на которые никто не жаловался. В третьей игре он был написан до публикации и поймал два расхождения ещё до того, как их кто-то увидел — это единственная из трёх, которая уехала к игроку целой.

Запустить у себя

git clone <репозиторий> && cd pipka
setsid -f xdg-open index.html >/dev/null 2>&1   # или просто открыть в браузере
node physics-test.js                              # прогон модели машины

Зависимостей и сборки нет: по папке на игру, HTML открывается прямо с диска. setsid -f нужен, чтобы Ctrl-C в терминале не убил браузер.

The red nub between the G, H and B keys is a TrackPoint; here it goes by pipka, which is what these games are named after. It reports pressure, not position: there is a strain gauge inside, and the pointer moves faster the harder your finger pushes. It is not a mouse — it is a miniature control stick that returns to zero by itself the moment you let go. These games are not built for "a mouse that happens to be a pipka"; they are built for pressure. Where an ordinary game reads cursor position, they read force.

Games

What this taught

Both games are about the same thing: a control has a character of its own, and a game works when it is built about that character rather than against it. The pipka can hold a force and cannot point precisely — so there is not a single pointing task in either game, and both are about holding an arc. The pipka returns to zero by itself — so a released finger means "straight ahead", and neither game needed a dead zone in its interface. The nub tells the finger nothing in return — so the tyre squeal, the pressure readout and the telemetry are not there to look nice.

And separately, not about game design at all: the first two times what shipped broken was precisely what I had not measured. The plane, because I checked the syntax rather than the build a human actually opens. The car, because I checked the track geometry numerically and left the dynamics to be eyeballed. The physics harness I should have written on day one found five bugs in a single run, three of which nobody had complained about. For the third game it existed before the first publish and caught two discrepancies before anyone saw them — the only one of the three that reached the player intact.

Run it yourself

git clone <repository> && cd pipka
setsid -f xdg-open index.html >/dev/null 2>&1   # or just open it in a browser
node physics-test.js                              # run the car model

No dependencies, no build step: a folder per game, the HTML opens straight from disk. setsid -f keeps Ctrl-C in the terminal from killing the browser.
